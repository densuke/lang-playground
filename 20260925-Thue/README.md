# Thue を試す (2026-09-25)

「古今東西 プログラミング言語紹介」2026-09-25 回 (難解言語枠) の実験環境です。
動画: <https://www.youtube.com/watch?v=Yu3gpYjpO24>

## 使い方

```bash
./run.sh sh -c 'python3 thue.py hello.thue'   # 直接動かす
./run.sh                                       # シェルに入る
./run.sh bash -s < demo.sh                     # 動画で流した順に実行する
```

`container` (macOS 26 の Apple container) / `docker` / `podman` のいずれかがあれば動きます。

## 処理系について

**自作の最小インタプリタ** (`demo/thue.py`、約60行) を使っています。標準ライブラリのみ。
Grass 回では「自作の処理系は静かに間違う」ため公式実装を使いましたが、Thue は仕様が
短く一意なので、以下の一次情報を確認しながら実装しています。

- 仕様: <https://esolangs.org/wiki/Thue> (作者 John Colagioia, 2000年発表)

確認した仕様のポイント:

- 書き換え規則は `<書き換え前>::=<書き換え後>` の1行1規則
- 規則の一覧は、`<書き換え前>` と `<書き換え後>` の両方が空 (または空白のみ) の行、
  典型的には単独の `::=` で終わる
- それ以降の行が初期状態 (複数行にまたがってよい)
- 実行は「現在の状態に部分文字列として現れる規則」を**非決定的に**選び、
  該当箇所を書き換え後の文字列で置き換える、を状態遷移が無くなるまで繰り返す
- 書き換え後が `~` で始まる規則は、マッチ箇所を削除したうえで `~` の後ろの文字列を
  出力ストリームに送る (状態には何も残らない)
- 書き換え後がちょうど `:::` の規則は、入力ストリームから1行読んでその場所に入れる
  (本実装でも `--seed` オプションと合わせて対応済みだが、同梱デモでは未使用)

非決定性はコマンドライン引数 `--seed` で乱数シードを固定できます (収録で結果を
再現するため)。仕様上は「候補の規則をどう選ぶか」まで規定されていないため、
本実装は「状態中に現れる規則を集めて `random.choice` で選ぶ」という単純な方法を
とっています (同じ規則が複数箇所にマッチしていても最初に見つかった位置しか
候補にしない簡略化あり)。

## 入っているもの

`demo/` の `.thue` ファイル3本は、[Issue #1](https://github.com/densuke/lang-playground/issues/1)
にあったとおり、実機で動作確認済みの素材をそのまま使っています。

| ファイル | 内容 |
|---|---|
| `demo/thue.py` | 自作インタプリタ本体 |
| `demo/hello.thue` | Hello World。1規則が発火して終了する最小構成 |
| `demo/inc.thue` | 単項数 (`_` で挟んだ `1` の並び) を2進数の桁上げ計算で処理する例 |
| `demo/nd.thue` | 同じ左辺 `x` を持つ2つの規則 (`~A` と `~B`) を用意し、非決定性を可視化する例 |

## 実行結果

```
$ python3 thue.py hello.thue
Hello World!
最終状態: ''

$ python3 thue.py inc.thue

最終状態: '10000000000'

$ python3 thue.py --seed 0 nd.thue
B
最終状態: ''

$ python3 thue.py --seed 1 nd.thue
A
最終状態: ''
```

`nd.thue` はシードを変えると `A` と `B` のどちらが出るか変わります。同じシードなら
同じ結果になります (収録・デモ用の配慮で、言語仕様そのものには乱数シードの概念はありません)。

「最終状態」の行は**インタプリタ側の便宜的な出力**で、Thue の出力ストリーム
(`~` による出力) とは別物です。プログラムが停止した時点で状態に何が残っているかを
デモ用に見せているだけなので、実際の Thue 処理系がすべてこれを表示するわけではありません。

## つまずきやすい点

**規則の適用順は保証されません。** `nd.thue` のように同じ左辺を持つ複数の規則があると、
実行するたびに (シードを固定しない限り) 結果が変わります。バグではなく仕様どおりの挙動です。

**出力用の規則 (`::=~...`) はマッチ箇所を「置き換え」ずに「削除」します。** そのため
出力しながら別の値を状態に残したい場合は、出力用と状態遷移用の規則を分けて設計する
必要があります (`inc.thue` のように、出力せず最後に状態だけ確認する構成の方が単純です)。

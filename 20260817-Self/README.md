# Self を試す (2026-08-17)

「古今東西 プログラミング言語紹介」2026-08-17 回の実験環境です。
動画: <https://www.youtube.com/watch?v=2LSIQ9LM3Jw>

## 使い方

```bash
./run.sh                          # シェルに入る。exit で抜ける
./run.sh self hello.self          # 直接動かす
./run.sh bash -s < demo.sh        # 収録と同じ順に全部動かす
```

`container` (macOS 26 の Apple container) / `docker` / `podman` のいずれかがあれば動きます。
初回のビルドには 15 分ほどかかります (理由は次の節)。

## 処理系について

公式の **Self 2024.1** (2024 年 8 月) を、GitHub のソース
(<https://github.com/russellallen/self>) からビルドしています。

Self の VM は **32 ビットの x86 (i386) 専用**です。公式の Handbook にも「Self is a 32bit
program」とあり、2024.1 のリリースノートでは、macOS が 32 ビットのプログラムを動かせなく
なったことを理由に macOS 版を取りやめています。VM は実行中に i386 の機械語を作って
走らせる作りなので、arm64 向けにビルドし直すだけでは動きません。

Apple Silicon の Mac では、`--platform linux/amd64` にしても動きません。Rosetta は
64 ビットの x86 しか扱えず、i386 のプログラムは `Exec format error` で止まります
(実際に試して確かめました)。そこで `Dockerfile` は 2 段構えにしています。

1. **ビルド段** (`linux/386`): ビルダーのエミュレーションで i386 の Debian を動かし、
   VM をソースからビルドします。続けて、GUI を読み込まない設定 (`-o none`) でソースから
   Self の世界 (オブジェクトの集まり) を組み立て、スナップショット `world.snap` に保存します
2. **実行段** (arm64): `qemu-user` と i386 のライブラリを入れ、VM を `qemu-i386` で
   動かします

`self` コマンドは、このスナップショットを読み込んでからファイルの式を評価する小さな
スクリプトです。エミュレーションなので、1 本の実行に数秒かかります。

動画では「Linux 向けのビルド済みバイナリが公式に」あると紹介しました。調べ直したところ、
公式サイトの「Download now!」にはリンクが無く、GitHub の 2024.1 リリースにも
ファイルが添付されていませんでした。そのためここではソースからビルドしています。

## 入っているもの

| ファイル | 内容 |
|---|---|
| `demo/hello.self` | 動画の `'here is some code' printLine` と、単項・二項・キーワードの 3 種類のメッセージ |
| `demo/slots.self` | 動画のスロット `x <- 3 + 4` と `y = 5`。書き換えられるのは `<-` のほうだけ |
| `demo/clone.self` | クラスを作らず、手本 (`counter`) を `copy` して使う。1 つのオブジェクトにだけスロットを足す |

## 実行結果

```
$ self hello.self
here is some code
120
7
9
here

$ self slots.self
7
5
10
true
false

$ self clone.self
3
1
0
only a has a name
false
```

`slots.self` の最後の 2 行は、オブジェクトに `x:` と `y:` というスロットがあるかを
ミラー (`reflect:`) に尋ねています。`x <- ...` と書くと、値を入れる `x:` も一緒に
作られます。`y = ...` のほうには作られないので、`y` は読み取り専用になります。

`clone.self` では、同じ手本から複製した `a` と `b` がそれぞれ別の `count` を持ち、
手本の `counter` 自身は 0 のままです。途中で `a` にだけ `name` を足しても、`b` には
ありません。

## つまずきやすい点

**ファイルの最後に `_Quit` を書きます。** 書かないと、式を評価し終えたあとに
対話環境のあいさつを出して入力を待ちます。`self` コマンドは標準入力を `/dev/null` に
しているので、その場合もすぐに終わりますが、余計な表示が出ます。

**途中でエラーが出ると、そこでファイルの評価が止まります。** 以降の行も `_Quit` も
実行されず、スタックトレースを出したあと対話環境に入ります。

**Handbook の構文例がそのまま動くとは限りません。** 言語リファレンスにキーワード
メッセージの例として載っている `5 min: 4 Max: 7` は、標準の世界には定義されて
いません。実行すると `min:Max:` が未定義というエラーになります。`hello.self` では、
実際にある `copyFrom:UpTo:` を 2 つの部分からなる例に使っています。

**VM は起動のたびに設定の一覧を標準エラーに出します。** `for I386: Inline = true`
のような行と `Reading ファイル名...` です。`self` コマンドはこの 2 種類だけを消し、
エラーの表示は残しています。

## ライセンス

`demo/` のコードは自由に使ってください。Self 本体は、著作権表示と免責の文言を残す
条件で、使用・改変・再配布を認めるライセンスで配布されています。Sun Microsystems と
Stanford 大学による Self 4.3 を元にしており、その部分には別のライセンスが付いています
(いずれもソースに同梱の `legal/LICENSE` と `legal/43LICENSE` による)。
